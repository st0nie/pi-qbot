`pi-qbot` (official QQ Bot API v2 bridge) uses one shared bot workspace/persona across QQ group and C2C chats: `Conversation.cwd` is `cfg.root`, and optional `<root>/PERSONA.md` is injected into every session. realctx therefore uses one shared project; group-specific memories must include the `group:<tag>` or `c2c:<tag>` marker and current chat path. Each chat has independent `groups|users/<openid>/.sessions`, `inbox`, and `.state.json` (refs, sent ids, nicknames). Incoming lines carry `[chat type:tag]`; never move attachments, transcripts, #N refs, or private facts between chats. `/qqbot restart` reloads persona/config/skills.

Inbound `quoteMsgId` is matched against `this.sent` (`(quote @me: ...)`) and `this.refs` (`(quote #N: ...)`), with a fast 600 ms debounce when quoted. Outbound `qq_send` supports `reply_to` (`#N` message number; anchors passive `msg_id` to `#N` if within `PASSIVE_WINDOW_MS` and sends `message_reference`) and `at` (nickname, `#N`, or an array of them). Bundled skills `skills/qq-quote-reply` and `skills/qq-mention` are loaded into every per-chat session via `additionalSkillPaths: builtinSkillPaths()` on `DefaultResourceLoader`. Pat/poke support (`qq_pat`, `detectPat`, and `skills/qq-pat`) was removed after live testing confirmed the gateway does not push poke/pat events.
